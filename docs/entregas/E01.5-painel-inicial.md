## O que foi entregue

- **Telas:** entrada, conta não habilitada, situação agora, unidades (lista e cadastro) e auditoria (filtro na URL e paginação).
- **Componentes:** `StatusChip`, `AnnunciatorWindow`, `EmptyState`, `PermissionNotice`, `ProblemNotice`, `ErrorBoundary`.
- **Contrato:** tipos do frontend gerados de `docs/api/openapi.v1.json` com `npm run api:types`. Se a API mudar, o build acusa.
- **Serviço web:** Nginx sem root, mesma origem para frontend e API, com CSP sem `unsafe-inline`.
- **API:** `GET /auth/status` para a tela de entrada explicar a falta de provedor, e `actorName` na auditoria (RF-037 pede "quem").

## Decisões de design

- **Painel de anunciadores:** a situação é uma faixa de janelas contíguas, como em uma central de alarme. Não há contadores grandes.
- **Verde só com confirmação:** contagem usa tom neutro, e o que não foi verificado usa `unknown`. Os equipamentos aparecem como "Sem informação" até o conector existir.
- **Atkinson Hyperlegible Next:** distingue 0/O e 1/l, o que importa para identificadores lidos sob luz intensa. Sem fonte externa, por causa da CSP.
- **Menu só com o que existe:** os itens de `docs/07-ux.md` entram junto com as telas deles, não como links vazios.
- **Interface esconde, API decide:** ocultar um item por permissão é só orientação; a autorização continua no servidor.
- **Fuso em lista:** os quatro fusos do Brasil com nomes compreensíveis. A API aceita qualquer nome IANA.

### Problemas encontrados pela verificação

- **Filtro da URL:** um valor arbitrário chegava à chamada da API, porque o roteador devolvia o texto original mesmo após `validateSearch`. Agora a tela também valida antes de usar.
- **Revisão visual:** contagem em verde, marca branca no modo escuro, fuso em texto livre e termos internos na auditoria. Todos corrigidos.
- **TypeScript:** o template não ligava `strict`. Foi ligado, e a versão foi fixada em 5.9 porque o gerador de tipos não aceita a 7.

### Da interface

4. **Logout:** `POST /auth/logout` encerra o cookie local, mas o redirecionamento ao provedor não é seguido, então a sessão no provedor continua. Resolver junto com a escolha do provedor.
5. **Gestão de equipe:** a API existe, mas a tela não. Por enquanto, conceder permissão exige chamar a API.
6. **Acessibilidade humana:** faltam leitor de tela, zoom real de até 400% e testes em luz intensa.
7. **Tempo de sessão visível:** pedido na skill de UX, ainda não implementado.
8. **Cartões em telas estreitas:** hoje a tabela só empilha as células; revisar quando houver listas densas.
9. **`/health/ready` pelo proxy:** fica público na mesma origem do frontend. Responde só o status, mas em produção pode ser restrito à rede interna.
